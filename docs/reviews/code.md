# Villar MVP: pre-launch code review

**Scope:** all first-party code. That covers `site/js/core/*`, `site/js/engine/**` (index, camera, interaction, furnish, lighting, sky, post, photo, probes, architecture, geo, util, proxies, materials, textures, furniture/*), `site/js/ui/*`, `site/js/main.js`, `site/index.html`, `site/css/*` and `vercel.json`. The deployed `site/lab/*` pages are included only for security. Vendor code was checked only for how we import and use it.
**Date:** 2026-11-25. **Reviewer:** code review (principal-engineer pass). No project files were modified.

## Method and how to read the numbers

- I read every file listed above, and I checked the relevant three.js r187 and three-gpu-pathtracer internals for each claim that depends on library behaviour (`Material.setValues`, texture upload caching, `projectObject`, `EffectComposer`, `WebGLShadowMap`, `WebGLPathTracer`).
- **Runtime checks** used a copy of `tools/shoot.mjs` with init scripts, eval results, network/long-task logging (`/tmp/rev/h.mjs`) and `window.villar.debug` + `window.villarUI.store`. Results are quoted as *harness*.
- **Pure-JS costs** (texture and sky generation) were timed in Node against the vendored three (`/tmp/rev/node/*`). These are quoted as *Node*.
- **Caveat:** the host has 2 CPU cores, SwiftShader WebGL and other agents running at load average 5–15. Absolute milliseconds are inflated. On a laptop they would be roughly 2–4× lower, and on a phone similar or higher. Functional results (races, wrong values, hangs) do not depend on speed.

## Summary

**34 findings: 1 × P0, 13 × P1, 20 × P2.**

Top issues:
1. **E1 (P0).** On iPhone and iPad the 3D studio never becomes ready. `probes.js` uses undefined `halfAtlas`, `halfStrip` and `fromHalf` whenever `EXT_float_blend` is missing, and no iOS device implements that extension. Users get a 45 s loader, then the 2D plan, while the engine keeps running underneath.
2. **E2 (P1).** Фото cannot be cancelled while it is preparing. Calling `stopPhoto` emits 'stopped', but path tracing starts anyway.
3. **E4 (P1).** Click-to-walk gets stuck against furniture. Nothing detects it, so the engine renders every frame forever.
4. **M1 (P1).** Fabric colours are wrong. The detail-map colour fix never reaches the material: linen is 13 % darker at load than the same colour created after a swap.
5. **E7 (P1).** Dome and bell pendants become 1° pencil spots, because the angle is passed in radians and read as degrees.
6. **E3 (P1).** `controls.mode`, `.view` and `.moving` are frozen by `Object.assign`. `villar.view` always returns 'eye'.
7. **E5 (P1).** Objects hidden in the dollhouse view (pendant, curtains, wall art) can still be hovered and clicked.
8. **M3 + C1 (P1).** There is a reflected XSS on the production origin via `/lab/furniture.html?tex=…`, and the site sends no CSP or security headers.

Also important for launch:
- **E8 + I2 + M2 (P1): mobile memory.** About 390 MB of texture memory on medium, plus another 268 MB in Фото. iPad also gets the 'high' tier.
- **E6 + I1 (P1): no user-visible fallback.** Nothing is shown when the WebGL context is lost or the engine never becomes ready.
